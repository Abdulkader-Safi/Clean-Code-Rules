What Claude does differently with the plugin on

It reads your code before writing and checks its own work before finishing.

Your codebase wins every argument

Before the first edit, Claude opens two or three files near the change. It matches how they name things, return errors and lay out tests. When a rule disagrees with your project, your project wins.

  1. 1Your project's tooling config
  2. 2Your language or framework's official style guide

  4. 4The 36 rules in this plugin

It checks its own diff for 12 AI habits

Before calling a change done, Claude reads the full diff and deletes what this list catches.

  • A new helper when one already exists
  • Interfaces with one implementation
  • try/catch at every level
  • Comments that narrate the code
  • Edits to files the task didn't touch
  • The model's style instead of yours
  • Dead code and unused imports
  • Tests that only test mocks
  • as any, ! or @ts-ignore to hide an error
  • TODO stubs presented as finished
  • Library methods that don't exist
  • A fix at one call site, not the root

It runs your tools

Formatter, linter, type checker and tests, found in your scripts or CI config. No new tool gets added without asking you.

$ npm run lint $ vendor/bin/phpstan $ dotnet test

Your context stays for your code

The skill file holds one line per rule. Claude opens a full rule, with examples, only when that rule applies.

Clean Code says functions should be two to four lines and comments are a failure. A Philosophy of Software Design says deep functions matter more, and missing comments cost more than wrong ones. In 2025 the two authors debated in public and agreed on most things. Where they agree, the rule is solid. Where they don't, these rules pick a side and say why.

How much of this is proven? Some of it.

Most design advice is convention: taught by experienced people, rarely tested. So every rule file ends with an evidence label. These are the studies the rules lean on.

36 rules, each one .md file you can read

Every file has the rule, why it works, a check, a bad and a good example, the fix and its sources. Examples are mostly TypeScript, with C#, PHP and SQL where the language changes the answer.

Rule 37 is a naming reference for each language. Rules 35 and 36 are the checks Claude runs before it finishes.
